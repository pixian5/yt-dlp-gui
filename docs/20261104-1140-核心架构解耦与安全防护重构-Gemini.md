# 核心架构解耦与安全防护重构（v0.1.3）

> 日期：2026-11-04 11:40 ｜ 版本：0.1.3 ｜ 作者：Gemini

## 一、 背景与目标

在版本 0.1.2 中，`guiapi/app.py` 演变为近 4,900 行的极端巨石单类（`YtDlpGUI`），承担了全部 UI 组件渲染、事件回调、475 行命令行参数拼装、子进程管道处理与状态机管理。项目存在以下隐患：
1. **安全隐患**：敏感认证凭据（`--password`、`--video-password`、`--twofactor` 等）以明文形式记录在执行命令日志中，持久化到 `run_gui.log` 和控制台标准输出；
2. **生命周期割裂**：Stop 停止按钮对「批量解析（Parse All）」阶段启动的外部进程无强杀控制，窗口关闭时容易遗留后台孤儿进程；
3. **单测覆盖不足**：缺少针对参数构造器（16 类选项）与多语言字典的自动化测试；
4. **历史死代码残留**：`guiapi/_legacy` 存有 1,448 行未接线的废弃代码，增加维护噪音。

本次重构旨在实现核心逻辑的自治分层解耦、补齐安全与测试防线、精简巨石代码。

---

## 二、 实施内容

### 1. 安全修复与凭据脱敏
- 在 `guiapi/core.py` 中实现 `sanitize_command(cmd: list[str]) -> list[str]`；
- 自动识别已知敏感参数（`--password`、`-p`、`--video-password`、`--ap-password`、`--twofactor`、`--token` 以及带凭据的 `--proxy`），在日志打印与磁盘输出前自动掩码为 `***`；
- 在 `app.py` 执行命令打印处无缝接入。

### 2. 生命周期闭环与强杀管理
- 在 `guiapi/app.py` 中引入 `_parse_all_process`，将 `parse_all_bulk_urls()` 原阻塞的 `subprocess.run` 改造为带超时的受控 `subprocess.Popen`；
- 打通 `stop_download()` 与 `on_closing()` 对解析中子进程的即时强杀，彻底消灭孤儿进程；
- 对齐下载按钮、Esc 键、`list_formats` 与 `extract_info` 的忙状态处理。

### 3. 核心领域逻辑解耦（四大新模块）
- **`guiapi/command_builder.py`**：
  - 抽离 475 行的参数组装为 16 类领域纯函数；
  - 引入 `OptionGetter` 适配层，统一适配 Tk 活跃控件、懒加载未构建页签（`_pending_gui_state`）与纯 Python `dict`。
- **`guiapi/runner.py`**：
  - 收敛 Homebrew / 系统路径下 `ffmpeg/node/deno` 工具链探测；
  - 封装跨平台进程组信号隔离（Unix `start_new_session` / Windows `CREATE_NEW_PROCESS_GROUP`）；
  - `terminate_process` 引入进程组防自杀保护，避免误伤 pytest 调用者自身；
  - 提供可流式读取输出并支持取消的 `SubprocessRunner`。
- **`guiapi/config_store.py`**：
  - 封装配置读写与损坏熔断恢复（`load_config_file` / `save_config_file`）；
  - 固化 `SECRET_CONFIG_KEYS` 并在持久化时自动过滤敏感项。
- **`guiapi/tab_builders.py`**：
  - 将 16 个懒加载通用页签的 UI 布局从 `app.py` 抽离，`app.py` 净减少 1,850+ 行代码。

### 4. 彻底清理废弃代码
- 物理删除 `guiapi/_legacy/` 目录（净清理 1,448 行死代码）；
- 同步清理 `pyproject.toml` 中的冗余排除规则。
